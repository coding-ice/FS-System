# 迭代器与生成器

## 1. 为什么需要迭代器

迭代器可以理解成一个“按顺序发牌的人”：每次你向它要一张，它就给你下一张；发完后明确告诉你“没有了”。

如果先创建一个很大的列表，所有数据都会一次性放进内存：

列表可以被遍历，但在数据量很大时会占用很多内存。迭代的思想是：**需要一个数据时，再取一个数据**，不用一开始把所有数据都准备好。

## 2. 自己编写一个迭代器

Python 中：

- 可迭代对象：能交给 `for in` 遍历的对象，例如 `list`、`tuple`、`set`、字符串。
- 迭代器：负责真正“取下一个元素”的对象。它既能被遍历，也会记住当前取到了哪里。

关系是：**迭代器一定是可迭代对象；可迭代对象不一定是迭代器。**

一个迭代器通常需要两个方法：

<<< @/backend/python/iterator-generator/code/2编写一个迭代器.py

- `__iter__()`：回答“谁是迭代器？”
- `__next__()`：回答“下一个元素是什么？”
- `StopIteration`：告诉 Python “已经没有下一个元素了”。

示例中用 `self.index` 记录已经取到第几个元素。每调用一次 `__next__()`，索引加一，因此迭代器会记住自己的遍历进度。

> 注意：迭代器遍历完后不会自动回到开头。再次遍历同一个迭代器时，不会有输出；要重新遍历，需要新建一个迭代器。

## 3. `for in` 和 `return self` 的关系

<<< @/backend/python/iterator-generator/code/3可迭代对象forin的实现.py

调用过程：

1. `for in` 先调用 `iter(stus)`，也就是 `stus.__iter__()`。
2. `__iter__()` 返回 `self`，意思是：`stus` 自己就是负责取下一个元素的迭代器。
3. `for in` 持续调用 `next(stus)`，也就是 `stus.__next__()`。
4. `__next__()` 依次返回元素；最后抛出 `StopIteration`，循环结束。

`return self` 的前提是：这个对象自己已经保存了数据和遍历进度（例如 `data`、`index`），并且实现了 `__next__()`；因此不需要再创建另一个专门的迭代器对象。
